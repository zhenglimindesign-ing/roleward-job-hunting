# 日常使用

[English](USAGE.md) | **简体中文**

完成[设置](GETTING-STARTED.zh-CN.md)后，使用自然语言即可。Roleward 应沿用背景、
提出有用的下一步，不要求你管理流程阶段。

| 你的请求 | 应得到的结果 |
| --- | --- |
| “这是我的简历和接下来想做的方向。” | 使用已有来源的结构化背景审核，只询问重要问题 |
| “找几个这周值得看的岗位。” | 遵守确认范围的有限实时搜索；零结果有效 |
| “这个岗位值得投入吗？” | 值得投入 / 先核实 / 放弃，附证据、重要缺口，以及必要时的具体核实计划 |
| “帮我确定这个岗位的定位。” | 可审核的 Positioning Brief，含最强证据和真实边界 |
| “按审核后的定位定制这份基础简历。” | 保留职业事实和重要证据、更相关的简历；环境支持时交付可编辑 DOCX 和 PDF |
| “准备求职信、联系人名单或联系短消息。” | 仅准备所需材料；零到三位可信联系人，不虚构背景 |
| “我今天投递了。” | 记录投递并给出已核实的保存回执 |
| “被拒了，没有说明原因。” | 记录结果，拒绝原因保持未知 |
| “从上次继续。” | 先读取已有状态再继续 |

## 运行一次 Scan

当前 Public Alpha 的 Scan 是**手动触发**的：

```text
帮我找几个这周真正值得关注的职位。
使用已经确认的地域和约束，不要为了凑数量返回结果。
```

底层 Scan contract 是 trigger-agnostic，之后可以由 scheduler 调用同一套流程；
但 production-grade 自动定时扫描目前还没有交付。
除非宿主能力和后续 Roleward 版本明确提供，否则不要把当前版本理解成后台自动监控。

## 更新偏好，不重建历史

```text
UAE 仍是主要市场，也考虑提供签证支持的荷兰岗位。
保留职业证据和之前的投递记录。
```

```text
以后每次最多给我三个岗位。这次只看一个。
```

长期限制应保存；单次限制只影响这次搜索。你的明确方向优先于推断偏好。
一次拒绝或放弃理由不应变成永久的市场规则。

## 准备简历

```text
使用这份基础简历和已经审核的岗位定位。
保留最强的相关证据，即使来自更早的经历。明确区分独立项目与正式生产经验。
给我可编辑的 DOCX 和 PDF。
```

Roleward 应选择和强调证据，不从头重建你的职业历史。提交前检查实际文件中的事实、
内容、联系方式和分页。文件保存在本地，绑定岗位来源和定位版本；任一变化后应准备新版本。
简历已准备不等于已经投递。

## 保守地记录与学习

```text
对方明确说需要更深入的生产 AI 产品负责经验。
记录这个理由，并解释单次结果能合理说明什么。
```

确认反馈可以支持学习。未经确认的原因仍是假设，不应据此改写你的目标。
Roleward 不监控收件箱，不替你投递或发送消息。

## 能力边界

没有实时网页访问时，可提供 Job/JD 分析。不能持久保存时，连续性只限当前对话。
缺少可选文档运行环境时，必须说明哪些文件格式尚未交付。
Skill 设计上可移植，但只有通过具体宿主验收后才会宣称支持该宿主。
当前支持范围见 [Alpha 状态](ALPHA-STATUS.md)和
[简历运行环境](RESUME-RUNTIME.md)。
