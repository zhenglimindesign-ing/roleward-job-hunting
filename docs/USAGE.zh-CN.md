# Roleward Job Hunting 使用指南

[English](USAGE.md) | **简体中文**

> 本文是 [USAGE.md](USAGE.md) 的中文翻译。如与英文版有出入，以英文版为准。

本指南说明可以向 Roleward 提出什么请求、它应该返回什么，以及几个主要工作流之间如何衔接。

Roleward 不是按功能菜单组织的。同一份持续积累的职业上下文，应该支撑整个闭环：

**了解我（Understand Me）→ 精准扫描（Precision Scan）→ 投入决策（Pursuit）→ 定位（Position）→ 人工审核（Human Review）→ 申请材料包（Application Pack）→ 跟踪（Track）→ 学习（Learn）**

你可以根据当前需要，从闭环的任何一个环节进入。

## 1. 建立或更新我的职业上下文

适用于：

- 第一次使用 Roleward；
- 你的简历或个人档案有变化；
- 你的求职方向有变化；
- Roleward 在基于过时或错误的假设做推理。

示例：

```text
这是我的简历和一段简短的职业说明。
帮我建立 Roleward 职业上下文。
先使用已有的内容再提问，把需要我审核的重要事实和假设列出来。
```

预期结果：

- 结构化的职业锚点（Career Anchor），而不是泛泛的个人简介；
- 当前的方向（Direction）；
- 地域（Geography）/ 远程范围；
- 工作许可状态（Authorization state）；
- 重要的证据和缺口；
- 只列出影响重大的冲突或缺失事实。

Roleward 应该区分有来源的事实、用户确认的事实和推断。

### 只更新一项，而不重建全部

```text
我现在的方向变了。我仍然想找高级产品职位，但 AI 不再是硬性要求。
更新已确认的方向，不要改写我的职业证据。
```

或者：

```text
你推断我更喜欢产品负责人类的职位，而不是偏交付部署的职位。我没有确认过这个偏好。
把它从已确认偏好中移除；如果有支持证据，只保留为未经确认的假设。
```

## 2. 找到值得投入的机会：精准扫描（Precision Scan）

适用于你希望 Roleward 发现当前的机会，而不是评估一个你已经找到的职位。

示例：

```text
找几个这周真正值得我关注的机会。
使用我已确认的搜索策略和当前地域。
不要为了多返回几个职位而放宽约束或凑数。
```

更具体的：

```text
在阿联酋和我们已经确认的 EMEA 远程范围内，扫描高级 AI/产品职位。
同时按职位名称和相关能力搜索；如果相邻类型职位的实际工作确实相关，也包括进来。
只返回值得审核的职位。
```

预期结果：

- 一份刻意精简的短名单，或者零个；
- 尽可能使用当前、权威的职位来源；
- 在宿主能做到时，验证链接是否有效；
- 硬性约束与软性匹配分开处理；
- 只有实际工作相关时，才纳入相邻的职位名称；
- 在支持持久化时，把机会存入本地储备池。

不应该出现：

- 50 个关系不大的职位；
- 悄悄把范围从阿联酋扩大到全球；
- 因为雇主是国际公司，就假定它会提供签证担保；
- 因为没达到请求的数量，就用较弱的结果填满短名单。

## 3. 评估一个职位：直接评估（Direct Opportunity）/ 投入决策（Pursuit）

适用于你已经有职位链接或 JD。

示例：

```text
这个职位值得我投入吗？
<职位链接>
```

或者：

```text
帮我评估这份 JD，告诉我它是否值得我花时间。
<粘贴的 JD>
```

主要输出应该是以下之一：

- **Pursue（值得投入）**：值得进入招聘流程；
- **Verify first（先核实）**：有一个会改变结论的事实，可以在进入流程前实际核实；
- **Pass（放弃）**：在当前已确认的上下文下，不值得投入。

辅助信号可能包括：

- 总体匹配度（Overall Match）；
- 能力匹配度（Capability Match）；
- 筛选可读性（Screening Legibility）；
- 职业价值（Career Value）；
- 受雇可行性（Employability）；
- 证据可信度（Evidence Confidence）。

这些都不是面试概率。

### 如何理解各个维度

**能力匹配度**：根据已展示的证据，你是否有可能胜任这份工作的实质内容？

**筛选可读性**：招聘方能否在不做过多推断的情况下，看懂一个真实的录用理由？

**职业价值**：如果你拿到这份工作，它能否实质性地帮助你当前的方向、职责范围、未来的市场信号或选择空间？

**受雇可行性**：把签证担保、工作许可、地点等结构性准入问题，与匹配度分开看。

### “先核实”应该是可执行的

好的例子：

```text
先核实（VERIFY FIRST）
这个职位在匹配度和职业价值上都很强，但需要职位级别的英国签证担保，目前情况未知。
在进一步投入之前，先查看具体的招聘需求，或向招聘方提一个具体的资格问题。
```

不好的例子：

```text
先核实（VERIFY FIRST）
弄清楚你入职后是否真的能对产品有影响力。
```

如果某个问题只能在面试中了解，Roleward 通常应该给出 `Pursue`（值得投入），并标注为**在流程中核实**，而不是卡住最初的决策。

## 4. 比较多个机会

适用于你手上已经有多个职位在争夺你的注意力。

示例：

```text
用我当前的 Roleward 上下文比较这三个机会。
告诉我应该先关注哪些，以及原因。
不要只按总体匹配度排序。

<职位 1>
<职位 2>
<职位 3>
```

有用的比较应该区分：

- 当下被录用的可信度；
- 对职业方向的提升空间；
- 结构性的可及性；
- 有意义的取舍；
- 会改变结论的未知因素。

一个分数略低的职位，如果录用理由和职业价值更强，仍然可能更值得关注。

## 5. 决定如何定位自己

在 Roleward 推荐 `Pursue`（值得投入）之后，或者你自己决定投入某个职位时使用。

示例：

```text
我想投这个职位。
在改写简历之前，先按你的建议生成定位简报（Positioning Brief）。
```

预期结果：

- 定位主张；
- 最有力的证据点；
- 要强调什么；
- 要淡化什么；
- 可信度上的缺口；
- 推荐的叙事方式。

这是申请准备中唯一必须经过的审核关卡。

### 生成材料前先修正定位

```text
我认同这些证据点，但我不想把自己定位成 AI 原生的产品经理。
改用“企业级产品 + 应用 AI 转型”作为叙事。
在生成任何对外材料之前，先更新定位简报。
```

Roleward 应该保存修订后的定位，并在后续环节使用这个版本。

## 6. 准备申请材料

定位审核通过后，只请求你需要的东西。

### 定制简历 / CV

```text
用审核过的定位简报，为这个职位定制我的简历。
每一条事实性描述都要以我已确认的职业证据为依据。
不要把独立的 AI 项目夸大成正式的生产环境经验。
```

简历、求职信等材料默认使用目标职位或市场的语言；如需其他语言，直接说明即可。

### 求职信

```text
这次申请有必要写求职信吗？
如果有，根据审核过的定位写一封简洁的；如果没有，告诉我跳过。
```

### 联系人

```text
为这个职位找最多三位可能值得联系的可信人选。
如果没有明显相关的人，零个也可以。
```

### 联络消息

```text
给最合适的联系人起草一条简短的 LinkedIn 好友邀请附言。
不要暗示我们认识，或者对方推荐了我。
```

Roleward 不应该自动投递申请，也不应该自动发送职业社交消息。

## 7. 跟踪一次申请

示例：

```text
我今天投了这个职位。把它标记为已申请（Applied）。
```

```text
我下周二有一次招聘方初筛电话。把这个机会更新为初筛中（Screening）。
```

```text
我撤回了申请，因为薪资低于我已确认的底线。
把结果和原因分开记录。
```

系统推荐和你的实际决定是分开的。你可以投一个 Roleward 建议放弃的职位，也可以跳过一个它推荐的职位，都不会改写历史评估。

## 8. 从结果中学习，但不过度拟合

### 被拒原因未知

```text
我被拒了，对方没有给原因。
记录为已拒绝（Rejected），但原因保持未知。
```

Roleward 不应该根据 JD 或你的档案去编造原因。

### 被拒原因已确认

```text
招聘方明确说他们需要更深的企业级 AI 部署经验。
按原话记录这个原因，并告诉我这是一次单独的观察，还是更大规律的一部分。
```

学习应该保守地逐步推进：

- **弱观察（Weak Observation）**：一条证据；
- **初现规律（Emerging Pattern）**：多次相互独立的证据；
- **已确认信号（Confirmed Signal）**：用户明确确认的事实，或经过适当晋升的状态。

一次被拒不能自动：

- 排除整个职位类别；
- 变成永久偏好；
- 覆盖已确认的方向；
- 把一个推断变成对外的事实性描述。

## 9. Roleward 出错时纠正它

当一个影响重大的假设出错时，你应该介入。

示例：

```text
这不对。钱包产品的工作确实是我直接负责的；更新已确认的证据，并保留原来的来源历史。
```

```text
不要把“偏交付”当成负面偏好。只要实际工作和职业价值合理，我对这类职位是开放的。
```

```text
你过分看重了我未来的方向，却低估了当前实际的匹配度。用已确认的上下文重新评估这个职位，不要把方向变成硬性约束。
```

Roleward 应该用新状态取代当前状态，但不抹掉之前的证据和历史。

## 10. 好用的提示词模式

### 开始求职

```text
阅读 SKILL.md，并使用 Roleward Job Hunting。
根据我提供的材料，帮我启动当前的求职。
```

### 寻找职位

```text
找几个这周真正值得我关注的职位。
精准优先，不求数量。零个也可以。
```

### 评估一个职位

```text
这个职位值得我投入吗？
<链接>
```

### 比较职位

```text
这些机会中，哪些应该先关注？每个的取舍是什么？
```

### 帮我定位

```text
我想投这个。在改简历之前，先生成定位简报。
```

### 定制申请材料

```text
用审核过的定位，只定制我真正需要的申请材料。
```

### 记录反馈

```text
这是招聘方的反馈。只记录明确确认的内容，并告诉我 Roleward 应该、以及不应该从中学到什么。
```

## 11. 当前 Alpha 的注意事项

- Codex 是主要测试宿主。
- 新的精准扫描需要宿主具备网页/搜索能力。
- 本地结构化持久化需要文件访问权限和 Python 3.11+。
- 生产级的定时扫描还不在本次公开 Alpha 的范围内。
- 可复用的用户级 Codex Skill 安装方式仍在做产品冒烟测试；当前推荐的 Alpha 流程是把仓库作为专用工作区。
- 推荐质量比分数能否精确复现更重要。
- 目前没有经过校准的初筛电话概率（Screening Call Probability）。

首次配置和隐私相关内容，见[入门指南](GETTING-STARTED.zh-CN.md)。
