# Roleward Job Hunting 入门指南

[English](GETTING-STARTED.md) | **简体中文**

> 本文是 [GETTING-STARTED.md](GETTING-STARTED.md) 的中文翻译。如与英文版有出入，以英文版为准。

Roleward Job Hunting 是一个 Codex 优先的 Alpha 版本，帮你更有章法地求职：了解你真实的背景，找到更少但更好的机会，判断哪些值得投入，真实地定位自己，并从结果中学习。

本指南介绍当前推荐的 Alpha 配置方式。

## 开始之前

如果你至少有以下其中一项，会得到最大的价值：

- 一份最新的简历或 CV；
- LinkedIn 或其他个人档案的导出；
- 职业笔记，或已有的 AI 职业上下文摘要；
- 对下一步想做什么的清晰描述。

你**不需要**全部都有。Roleward 应该先利用已有的材料，再请你补充缺口。

当前 Alpha 的要求：

- 具备本地文件访问权限的 Codex；
- Python 3.11+，用于本地持久化和辅助脚本；
- 如果要做实时的新职位扫描，宿主需要具备网页/搜索能力。

## 推荐的 Alpha 配置：专用 Codex 工作区

当前推荐的方式，是直接把这个公开仓库作为专用的本地求职工作区。

### 第 1 步：把仓库放到本地

仓库地址：

`https://github.com/zhenglimindesign-ing/roleward-job-hunting`

你可以自己克隆或下载，也可以在已有的本地工作区里让 Codex 帮你克隆：

```text
帮我把 https://github.com/zhenglimindesign-ing/roleward-job-hunting 克隆到一个本地文件夹。
克隆后不要修改仓库内容。告诉我最终的文件夹路径。
```

然后在 Codex 中把得到的 `roleward-job-hunting` 文件夹作为当前项目打开。

### 第 2 步：启动 Roleward

已有简历、首次配置时：

```text
阅读 SKILL.md，并使用 Roleward Job Hunting。

这是我的简历。帮我建立职业上下文和当前的求职方向。
先使用我已经给你的材料，再向我提问。
把对我下一步行动有影响的重要事实、假设、冲突和缺失项列出来。
```

如果简历已经保存在本地，可以把它放进 `sources/`，然后告诉 Codex 文件位置。

如果手头没有合适的简历：

```text
阅读 SKILL.md，并使用 Roleward Job Hunting。

我想开始求职，但手头没有整理好的职业概要。
只问建立我的职业锚点、方向、地域和工作许可状态所必需的问题。
```

你可以直接用中文与 Codex 交流。Roleward 应该用你使用的语言回复；保存到本地状态的字段名和取值仍保持英文。

### 第 3 步：审核你的上下文

Roleward 不应该生成一份不透明的档案，然后马上开始做判断。

在第一次大范围扫描之前，至少审核以下几项：

- **职业锚点（Career Anchor）**：你的实际经历和最有力的证据；
- **方向（Direction）**：你接下来想要的职位类别、能力方向或转型目标；
- **地域（Geography）**：认可的工作地点和远程范围；
- **工作许可状态（Authorization state）**：例如 `No sponsorship`（不需要签证担保）、`Sponsorship required`（需要签证担保）、`Depends`（视情况而定）或 `Not sure`（不确定）。

Roleward 会区分：

- **源材料（Source Material）**：简历、文件或外部来源中写了什么；
- **已确认事实（Confirmed Truth）**：你明确确认过的关于自己的事实；
- **推断信号（Inferred Signal）**：有边界的假设，不能悄悄变成硬性事实。

如果有影响重大的内容写错了，直接在对话中纠正。Roleward 应该保留你的更正，用新状态取代旧状态，而不是改写历史。

## 三种好用的开始方式

### A. 从你的职业上下文开始

```text
这是我的简历，以及一段关于下一步想做什么的简短说明。
帮我建立一份有依据的 Roleward 职业上下文，并告诉我在第一次扫描前还需要什么。
```

适合你希望 Roleward 成为长期求职伙伴的情况。

### B. 马上评估一个职位

```text
这个职位值得我投入吗？
<职位链接，或粘贴的 JD>
```

Roleward 应该利用已有的候选人上下文来分析这个职位。如果缺少某个只有你本人知道、且可能实质性改变结论的事实，它可以向你询问。

### C. 运行一次精准扫描

```text
找几个这周真正值得我关注的职位。
只在我已确认的地域和约束范围内找。
如果没有足够好的，不要凑数。
```

预期结果是一份**很短的名单，或者零个**，而不是一长串看起来还行的职位。

## 本地状态与隐私

把本仓库作为专用的 Alpha 工作区时，辅助脚本会用到以下本地运行时目录：

- `state/roleward-state.json`：结构化的当前状态；
- `sources/`：简历、AI 上下文导出等私有源材料；
- `application-files/`：在本地持久化时生成的申请材料。

这些运行时文件已被仓库的 `.gitignore` 排除。

重要提示：

- 不要提交你的简历、私人职业上下文、申请历史或本地状态；
- 除非你了解 schema，否则不要手动编辑 `state/roleward-state.json`；
- 尽量在对话中纠正上下文，这样来源追溯和版本取代记录才能保留下来；
- 如果确实想彻底重置，先备份本地状态，不要随手删除历史。

Roleward Alpha 不需要生产后端。你的本地状态不会自动同步到 Roleward 的网页产品。

## 选择“值得投入”之后会发生什么？

Roleward 不应该直接跳到改写简历。

预期的顺序是：

1. 职位被评估为 `Pursue`（值得投入），或者你明确选择投入。
2. Roleward 生成一份**定位简报（Positioning Brief）**。
3. 你审核并修正这份定位。
4. 之后，Roleward 才会生成你真正需要的对外材料：
   - 定制的简历 / CV；
   - 有必要时的求职信；
   - 0–3 位可信的联系人；
   - LinkedIn 好友邀请附言 / InMail 草稿。

这一步人工审核，是为了让后续材料始终建立在你真正想要的职业呈现方式之上。

## 之后更新搜索设置

你可以在对话中直接修改方向或约束：

```text
更新我的求职方向：阿联酋仍然是首选，但如果能提供签证担保，我现在也想考虑荷兰的职位。
不要改动我现有的职业锚点。
```

或者：

```text
我不再想优先考虑这类职位。把它作为一次已确认的偏好变更，而不是从之前的被拒中得出的结论。
```

Roleward 应该保留之前的状态和历史，并在之后按新的已确认状态执行。

## 记录结果

示例：

```text
我今天投了这个职位。把它标记为已申请（Applied）。
```

```text
我在招聘方初筛后被拒了，对方没有说明原因。
更新结果，但不要推测我被拒的原因。
```

```text
对方明确说他们需要更深的企业级 AI 部署经验。
把这条记录为已确认的拒绝原因，并告诉我 Roleward 应该从中学到什么（如果有的话）。
```

一次结果不应该变成永久的市场规律。

## 更新 Roleward 本身

如果你是克隆的仓库，在开始新一轮测试前，或在有文档说明的新版本发布后，把本地代码更新到最新的 `main`。

由于可复用的 Codex 用户级安装方式仍在做产品冒烟测试，目前推荐的 Alpha 配置仍是专用仓库工作区。

## 常见问题

### Codex 在介绍 Roleward，而不是使用它

明确告诉它：

```text
阅读 SKILL.md，并用 Roleward Job Hunting 的工作流处理这个任务。除非必要，不要向我复述这个 Skill 的内容。
```

### Roleward 一直问简历里已经有的内容

告诉它：

```text
先使用已有的源材料，再向我提问。只问会实质性改变当前决策的缺失信息。
```

反复问不必要的问题属于产品质量问题，欢迎反馈。

### 实时扫描无法验证当前职位

宿主需要具备实时网页/搜索能力。没有这项能力时，Roleward 仍然可以分析你提供的 JD，但不应该声称做了一次新的扫描，或验证了当前的签证担保情况和链接有效性。

### 每次运行的数字都不一样

把显示的分数当作方向性信号，而不是概率。主要输出是推荐结论（`Pursue` 值得投入、`Verify first` 先核实、`Pass` 放弃），以及背后的证据和理由。

### 我想在所有 Codex 项目里都能用 Roleward

Codex 支持可复用的用户级 Skill，但 Roleward 公开的一步安装/更新体验仍在验证中。在这套流程完成端到端冒烟测试之前，当前 Alpha 文档有意推荐专用工作区的方式。
