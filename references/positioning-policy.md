# Positioning Policy

After a user chooses to pursue a role, generate a concise Positioning Brief before outward application materials.

Required content:

- positioning thesis
- strongest proof points
- what to emphasize
- what to de-emphasize
- credibility gaps
- recommended narrative

The user must confirm or correct the Positioning Brief. The reviewed revision becomes the grounding source for CV, cover letter, contacts/outreach framing.

## Truthfulness

- Prefer the strongest truthful proof, not maximum keyword overlap.
- Do not disguise a credibility gap.
- Do not elevate independent-builder work into professional production experience.
- Do not invent years, scope, ownership, metrics, seniority, employers, or domain experience.
- Keep downstream artifacts consistent with the reviewed Positioning revision.

## Revisions and source changes

Store draft, reviewed content and artifact metadata as independent snapshots;
later caller edits must not rewrite earlier revisions. When a job source changes,
keep historical materials but create and review positioning against the current
source before recording new outward materials. Re-observing identical job
content does not invalidate a review. Bind a new positioning draft to a Pursuit
assessment only when that assessment uses the same current job snapshot.

If an artifact specifies a local file, save that file before recording its
provenance; do not claim a missing file as a delivered artifact. Factual accuracy
and human approval still require host/user review beyond reference validation.

For resume tailoring and file delivery, read [Resume policy](resume-policy.md).
Use the base resume as the artifact baseline rather than rebuilding career
history from Career Evidence.
